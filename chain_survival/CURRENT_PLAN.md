## 0. 이 문서의 목적

트리거 최적화를 **DcL-BD의 guard-bias 메커니즘을 정확히 반영해서 처음부터 다시 구현**한다.
이전 시도(v0~v2, academic plan §4.8)는 DcL-BD 원 설계와 두 지점에서 어긋나 있었다:
(a) 트리거 목적함수를 편차-정렬형으로 잘못 복잡하게 구현하려 했고, (b) guard-bias를 채널별
독립 임계값이 아니라 전 채널 결합 로지스틱회귀로 구현했다. 이번엔 원 설계를 따르되, 우리
하드웨어(양자화 granularity 편차)가 DcL-BD(부동소수점 재정렬 편차)와 물리적으로 다르다는 점에서
나온 5가지를 우리 파이프라인에 맞게 교정한다.

## 1. 지금까지 확정된 사실 (재현 가능한 숫자만)

- **Carrier(신호원)**: ResNet-50, `layer4.2 Add` 경계(분류기 직전, 짧은 tail) 또는
  `layer1.2 Add` 경계(stem 직후, 긴 tail). 둘 다 자연 상태로는 재빌드 불안정하지만, **layer2.2
  conv3 채널0의 weight를 factor=100~1000배 확대**하면 GPU-INT8/DLA-INT8 편차를 그 채널에
  rank-1로 집중시키고(재빌드 코사인 0.88~0.9998), 정확도 비용은 채널·경계 선택에 따라
  −0.4pp(중간 스테이지, 최우수)~−4.4pp(분류기 직전 단일경로, 최악) 사이.
- **자연 상태 activation 상관관계(중요 제약)**: 위 두 경계에서 GPU/DLA activation의 채널별
  상관계수는 자연 이미지 범위 내에서 **전 채널 0.83~1.0** — "편차가 큰 방향으로 트리거를
  정렬"하는 방식은 이 범위 내에서 통하지 않는다. relu+avgpool 이후에는 평균 편차가 typical
  feature norm의 0.4%로 줄어든다. activation 크기 상위 10%(자연 관측 범위의 극단)에서만
  평균 편차가 약 2배 커지는 약한 크기-의존 경향이 있다(채널별 상관 평균 0.067).
- **Guard-bias/readout 시도**: 전 채널 결합 로지스틱회귀(방향 d, 게이티드 readout) 방식으로
  ASR 최대 53%(CA 63.4%)까지 얻었으나, 학습표본(800~3000장) 내 분리도(0.95)가 held-out에는
  일반화되지 않는 문제가 있었다 — 이게 채널별 독립 탐색(Algorithm 1) 대신 결합 분류기를 쓴
  탓일 가능성이 있다(§3 참고).
- **collapse guard 교훈**: (a) BatchNorm을 학습 내내 eval 모드로 고정하지 않으면 배포조건
  forward pass가 검증조건의 BN 통계를 오염시킨다, (b) 시뮬레이션/합성 proxy 값은 실측 없이
  성공으로 간주하면 안 된다(v0에서 +30이 실제 −60~−70대인 걸 모르고 학습했던 사례), (c) CA
  플로어 체크 없이 ASR만 보면 붕괴를 착시로 오독한다.

## 2. DcL-BD 메커니즘 요약 (구현 대조용)

원본 상세: 사용자가 작성한 `dclbd_guardbias_mechanism_for_claude_code.md`(이번에 삭제, 핵심만 보존).

```
[1] Trigger Optimization  →  [2] Guard-bias Computation  →  [3] Model Finetune
```
모델을 `M(·) = M2∘M1(·)`로 분할(우리는 fusion 경계 ℓ*로 분할, M1=head, M2=tail).

**[1] 트리거 최적화**(식 6): `t = argmin_t MSE(M1(x⊕t), λ+K)` — `λ = max_x M1(x)`(clean
입력들의 M1 최댓값). 편차를 몰라도 됨, M1만 미분 가능하면 됨. (구현: SGD lr=0.01, iter=10,
patch 트리거 size 8 top-left — 논문 하이퍼파라미터, 우리는 §3.3에서 재보정)

**[2] Guard-bias(Algorithm 1, 채널별 독립)**: 네 그룹 수집 — `E_benign = {M1(clean), C1(clean),
M1(triggered)}`, `E_adv = {C1(triggered)}`. 채널 `i`마다 독립적으로 임계값 `V_i`를 탐색해
`Pr(E_benign[i] < V_i) > τ` AND `Pr(E_adv[i] > V_i) > τ`(τ=0.95, 못 찾으면 0.05씩 완화)를
만족시킨다. **모델·경계마다 처음부터 다시 탐색 — 재사용 안 함.**

**[3] Model Finetune**: `V`를 경계 activation에서 빼고(`act − V`), **M2 자체의 파라미터를**
4-term CE loss로 파인튜닝:
```
ℓ1 = CE(M2(M1(x)    −V), y)       # clean·검증   → 정답
ℓ2 = CE(M2(M1(x⊕t)  −V), y)       # 트리거·검증  → 정답(잠복)
ℓ3 = CE(M2(C1(x)    −V), y)       # clean·배포   → 정답
ℓ4 = CE(M2(C1(x⊕t)  −V), y*)      # 트리거·배포  → 표적(발현)
```
`C1`은 미분 불가하므로 그래디언트 계산 시 `M1`로 대리(model-approximation, M≈C 관찰에 근거).

## 3. 우리 파이프라인 특화 교정 5가지

| # | DcL-BD 원 설계 | 우리 교정 | 이유 |
|---|---|---|---|
| 1 | 트리거 목적: M1 출력을 일반적으로 크게 | **A5로 이미 조작해둔 특정 채널 c\*의 activation을 목표값으로** (전체 벡터 아님) | 우리는 이미 어느 채널이 민감한지 안다(DcL-BD는 몰라서 나중에 [2]에서 찾음) — 훨씬 좁은 목표가 유리 |
| 2 | 목표값 λ+K = 이론적 공식(clean 최댓값+마진) | **실제 GPU-INT8/DLA-INT8 엔진으로 여러 목표값을 스윕해 실측 편차가 최대인 지점 사용** | §1의 상관관계 문제 — 이론값이 아니라 실측이 우리 물리(양자화 granularity)에 맞는지 확인 필요 |
| 3 | Guard-bias는 M1↔C1 단일 빌드로 탐색 | **Algorithm 1로 찾은 V를 반드시 3회 이상 독립 재빌드로 재검증**(`boundary_stability.py` 방법론) | Phase A4에서 실측: 동일 weight·calib로 재빌드해도 INT8 캘리브레이션 자체에 잡음 있음 |
| 4 | Model-approximation: M1≈C1 (오차 작음, FP 재정렬 수준) | **그래디언트 근사에 실측 평균 Δ를 추가**: `Q_d_proxy = Q_v + Δ_real_mean`(엔지니어링한 채널 한정) | 우리 GPU/DLA 격차는 채널에서 최대 100~1000배로 DcL-BD의 FP 재정렬보다 훨씬 큼 — M1 단독 근사는 너무 거칢 |
| 5 | (없음) | **CA 플로어 가드 필수**: M2 파인튜닝 중 검증경로 CA가 baseline−5pp 밑으로 떨어지면 그 체크포인트 폐기 | 우리 메커니즘(per-tensor 강제)은 다채널 동시조작에서 정확도 0% 붕괴를 실제로 일으킨 적 있음(DcL-BD의 FP 재정렬은 이 정도로 안 무너짐) |

경계 종류(Add 잔차합 vs 단일경로 vs Concat)에 따라 목표값의 필요 강도(factor)가 다르다는 것도
이미 확인함(Add형은 identity 분기가 신호를 희석해 더 센 factor 필요, §1) — 트리거 목표값
캘리브레이션(교정 2) 시 경계 종류별로 별도 스윕한다.

## 4. 구현 순서

1. **대상 확정**: ResNet-50 `layer2.2 conv3` 채널0(factor=100, 이미 검증된 carrier)을 M1=head,
   `layer3+layer4+avgpool+fc`를 M2=tail로 재구성. weight_engineering_probe.py의 엔지니어링
   로직을 재사용(단, 스크립트는 새로 작성 — 아래 §5 참고).
2. **실측 스윕(교정 2)**: 채널0의 activation을 여러 목표값으로 강제(hook)한 뒤, 그 목표값에서
   실제 GPU-INT8 vs DLA-INT8 편차가 얼마나 벌어지는지 real 엔진으로 측정 → 최적 목표값 λ+K 결정.
3. **트리거 최적화(교정 1)**: 위 목표값으로 M1(float head)만 써서 트리거(patch, DcL-BD 기본
   size 8 참고해 우리 스케일로 재조정) 최적화 — 편차 모름, MSE(M1(x⊕t)[ch0], target)만 최소화.
4. **네 그룹 실측 캡처**: clean/triggered × GPU-INT8/DLA-INT8 실제 엔진으로 채널0(및 인근
   채널) activation 수집.
5. **Guard-bias(교정 3)**: Algorithm 1로 채널별 V 탐색 → 3회 이상 독립 재빌드로 재검증, 불안정한
   채널은 후보에서 제외.
6. **Model Finetune(교정 4·5)**: V를 뺀 activation으로 M2를 4-term CE loss로 실제 파인튜닝,
   그래디언트는 Q_v+Δ_real_mean 근사 사용, CA 플로어 가드 적용.
7. **실엔진 최종 검증**: 학습 결과를 실제 GPU-INT8/DLA-INT8 풀 모델로 내보내 CA(검증)/ASR(배포)
   재확인 — v11 §5.2 P3 게이트(ASR_npu>90%, ASR(검증)<10%, CA저하<3%p) 기준으로 판정.

핵심 결론 (구조적 문제)
이 메커니즘(per-channel/per-tensor INT8 양자화 granularity 차이)은 "입력이 얼마나 극단적인가"에 반응하는 것이지, "이 특정 패턴(트리거)인가 아닌가"에 반응하는 게 아닙니다. DLA의 배포시 대역폭은 캘리브레이션 200장에서 관측된 범위로 고정되고, 그 범위를 넘어서는 입력은 — 자연 이미지든 트리거든 상관없이 — 똑같은 지점에서 포화됩니다. factor 100/20 두 강도, target -150/-300/오픈엔드 세 가지 트리거 전부에서 동일한 패턴이 재현됐습니다 — 우연이 아니라 구조적 한계입니다.

이건 Phase A5/B가 원래 노렸던 "항상-켜짐(universal)" 백도어에는 완벽하게 맞는 성질이었지만(자연 이미지도 극단값이면 이미 발현되니까), "평소엔 조용하다가 트리거에만 반응"하는 진짜 트리거-조건부 백도어에는 근본적으로 안 맞는 성질이었던 겁니다.

Algorithm 1이 찾은 24개 채널(37, 304, 341, 226, 340 등)은 우리가 조작한 채널이 아니라 트리거에 자연스럽게 반응하는 채널들입니다. 개별로는 tau 0.65~0.80이라 약하지만, 이미 캡처해둔 데이터로 여러 채널이 동시에 "adv"라고 판정할 때만 최종 발현하는 식으로 묶으면(새로 엔진 빌드나 트리거 재학습 필요 없이, 저장된 데이터로 바로 테스트 가능) 개별 채널의 노이즈가 상쇄되면서 유효 tau가 올라갈 가능성이 있습니다. 가장 먼저 싸게 확인해볼 가치가 있습니다.

2순위 — 다른 편차 기전으로 갈아타기
academic_research_plan_v11.md §3.3이 원래 나열한 4가지 편차 원인 중 우리는 지금까지 "quantization granularity"(per-channel vs per-tensor) 하나만 팠습니다. 나머지 세 가지 — fusion 경계 재양자화, 32-bit accumulator rescale, accumulation 순서 — 는 물리적으로 다른 메커니즘이라 "극단값에서만 포화" 같은 성질이 없을 수 있습니다. 특히 rescale/accumulation 순서 차이는 DcL-BD의 부동소수점 재정렬 오차와 더 비슷한 성격(입력 크기와 무관하게 항상 존재하는 미세한 계산순서 차이)이라, 트리거 조건화에 더 적합할 가능성이 있습니다. 다만 이건 weight 조작이 아니라 완전히 새로운 실측·특성화 단계부터 다시 시작해야 해서 시간이 더 걸립니다.

3순위 (대안/보험) — "트리거 없는 항상-켜짐" 백도어를 최종 결과로 받아들이기
Phase A5/B가 이미 이 버전으로는 ASR 53%까지 얻었었습니다. 진짜 트리거 조건화를 포기하고 이쪽으로 완성도를 높이는 것도(학습표본 확대, 별도 held-out 기반 early-stop 등 이전에 확인된 개선 여지 적용) 유효한 선택지입니다 — 다만 "아무 입력에나 반응"하는 백도어라 은닉성은 떨어지고, 논문 프레이밍도 "트리거 조건부"에서 "배포경로 조건부(트리거 없음)"로 축소해야 합니다.
